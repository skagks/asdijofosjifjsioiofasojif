# 몬스터 헌터 와일즈 모드 매니저

Monster Hunter Wilds(몬스터 헌터 와일즈) PC판용 모드 관리 프로그램입니다.
Nexus Mods 등에서 받은 모드 압축 파일을 끌어 놓기만 하면 설치되고, 체크박스로 켜고 끌 수 있으며,
게임 폴더에 넣은 파일을 모두 기록해 두었다가 깨끗하게 되돌립니다.

![모드 매니저 화면 (다크 테마)](docs/screenshot-dark.png)

## 주요 기능

- **압축 파일 그대로 설치**: zip / 7z / rar / 폴더 / 단일 `.pak`·`.lua`·`.dll` 파일
  - 압축 안의 폴더 구조를 분석해서 게임 폴더 기준 위치를 자동으로 찾습니다.
  - Fluffy Mod Manager 형식(`modinfo.ini`)의 이름·제작자·버전·설명·미리보기 이미지를 읽습니다.
  - 옵션이 여러 개 들어 있는 압축 파일은 **모드 하나로 설치**되고, 옵션은 설치한 뒤 언제든 **옵션** 탭에서
    켜고 끌 수 있습니다. 처음에는 모든 옵션이 꺼져 있으니 사용할 옵션을 골라 주세요(여러 개 함께 켤 수 있음).
    옵션마다 미리보기 그림이 있으면 옵션 옆에 썸네일로 보여 주고, 누르면 크게 볼 수 있습니다.
    옵션 그림이 없는 모드(1.12.0 이전에 설치한 모드 등)는 옵션 탭의 **압축 파일에서 옵션 그림 가져오기**(또는 메뉴의
    **옵션 그림 다시 찾기**)로 설치할 때 쓴 압축 파일에서 그림만 가져올 수 있습니다.
  - Nexus 파일 이름(`이름-123-1-2-1740000000.zip`)에서 모드 이름과 버전을 뽑아냅니다.
  - 한글 파일 이름이 들어 있는 zip(cp949)도 깨지지 않습니다.
- **모든 모드 형식 지원**
  - 루스 파일 모드 (`natives/STM/...`)
  - PAK 모드 — 게임 폴더의 `pak_mods` 폴더에 로드 순서대로 넣어 REFramework가 불러오게 합니다
  - REFramework 스크립트/플러그인 (`reframework/autorun/*.lua`, `reframework/plugins/*.dll`,
    `reframework/` 폴더 없이 `autorun/`만 들어 있는 경우 포함)
  - REFramework 자체(`dinput8.dll`)와 기타 DLL 모드
- **장비 외형 보기**: 모드가 게임 속 어떤 장비(방어구 · 무기 · 오토모 장비 · 세크레트 · NPC 등)의 모습을 바꾸는지
  게임의 장비 이름과 미리보기 그림으로 한눈에 보여 줍니다. 방어구는 남성 · 여성과 부위(머리 · 몸통 · 팔 · 허리 · 다리)별로,
  같은 부위를 바꾸는 모드끼리는 **겹침**으로 표시합니다. 루스 파일 모드와 PAK 모드 모두 살펴봅니다.
  모드를 적용한 모습을 간단한 3D 그림으로 그려 원래 모습과 나란히 비교할 수도 있습니다 (**적용 후 미리보기**).
- **켜기/끄기와 로드 순서**: 체크박스로 켜고 끄며, 드래그 또는 ▲▼ 버튼으로 순서를 바꿉니다.
  목록 아래쪽 모드일수록 우선 적용됩니다.
- **충돌 한눈에 보기**: 같은 파일을 바꾸는 모드끼리 몇 개의 파일이 겹치고 어느 모드가 이기는지, 아무것도 적용되지 않는 모드가
  있는지 한 창에서 보여 줍니다. 모드를 고르면 그 모드를 덮어쓰는 모드(보라)와 그 모드에 밀리는 모드(청록)가 목록에 표시됩니다.
- **문제 있는 모드 표시**: 옵션을 하나도 켜지 않았거나, 필요한 모드가 없거나, 파일이 모두 밀려 제대로 작동하지 않는 모드는
  목록에서 빨간 줄과 ⚠로 표시하고, 마우스를 올리면 이유를 알려 줍니다. 목록 제목 옆 **⚠ 문제 N개**를 누르면 그 모드만 보입니다.
- **필요한 모드 알림**: 설치한 모드에 필요한 다른 모드(Nexus 모드 페이지의 Requirements, 스크립트가 불러오는 Lua 라이브러리,
  재질이 쓰는 셰이더 팩)가 없거나 꺼져 있으면 알려 줍니다.
- **모드 수정**: 다른 사람이 만든 모드를 내 입맛대로 고칩니다. 넣지 않을 파일 빼기 · 옵션끼리 겹치는 파일 고르기,
  데이터 모드(.user)의 값(보상 · 확률 · 가격 등) 바꾸기(예: 5배 모드를 2배로), 스크립트 모드의 설정 파일(Lua · JSON ·
  INI · TOML) 값 바꾸기. 모드의 원래 파일은 그대로 두고 언제든 되돌리며, 모드를 업데이트하면 수정을 새 파일에 다시 적용합니다.
- **다른 장비로 옮기기**: 외형 모드가 바꾸는 방어구 · 무기 대신 다른 장비를 바꾸는 새 모드를 만듭니다(같은 종류끼리,
  방어구는 머리는 이 장비 · 몸통은 저 장비처럼 부위마다 다른 장비로도).
  대상 장비가 옮긴 모델을 실제로 읽는지 게임 파일로 먼저 확인합니다.
- **재질 복구 (MHW Mod Fixer 기능)**: 게임 업데이트로 재질(.mdf2)이나 .user·.pfb 파일 구조가 바뀌어 텍스처가 깨지거나
  게임이 멈추는 의상·무기 모드를 찾아 현재 게임에 맞게 그 자리에서 고칩니다. 모드의 원래 파일은 그대로 두고 언제든 되돌릴 수 있습니다.
- **실행 전 점검**: 게임을 켜기 전에 게임이 튕기거나 모드가 작동하지 않는 흔한 원인(꺼져 있는 REFramework 설정,
  맞지 않는 재질, pak_mods의 PAK 개수, 직접 넣은 DLL · 파일, 지난번 게임에서 읽지 못한 모드 파일 등)을 찾아 새로 생긴 것만
  알려 줍니다. 실행을 막지는 않으며, REFramework 설정은 묻고 나서 고칩니다.
- **게임 튕김 기록**: 게임이 튕기면 REFramework가 남긴 기록(다음 실행 때 지워짐)을 미리 챙겨 두었다가, 어디서 오류가 났는지와
  의심되는 모드를 근거와 함께 보여 줍니다. 게임 오류 창 문구를 붙여 넣어 분석하거나, 문제를 알릴 때 보낼 진단 파일(zip)을 만들 수 있습니다.
- **원인 모드 찾기**: 기록만으로 모드를 알 수 없을 때 모드를 켜고 끄며 실행해 보고 게임을 튕기게 하는 모드를 찾습니다.
  튕김 기록 · 지난 실행 · 재질 상태로 모드마다 의심되는 정도(%)를 먼저 매기고, 실행할 때마다 가장 많이 좁힐 수 있는 조합을
  고르며, 답 하나가 틀려도 엉뚱한 모드를 짚지 않도록 근거가 충분할 때만 가능성과 근거를 붙여 결과를 냅니다. 지금 프로필은
  그대로 두고 임시 프로필에서 진행하며, 게임이 끝나면 종료 코드와 기록으로 튕겼는지 확인해 "또 튕겼나요?"의 답을 미리
  골라 둡니다.
- **안전한 적용/해제**
  - 게임 폴더에 넣은 파일을 모두 기록하고, 바뀐 부분만 복사·삭제·이름 변경합니다.
  - 모드가 원래 게임 파일을 덮어쓰면 백업해 두었다가 모드를 끌 때 복원합니다.
  - 모드를 끄면 비게 된 폴더까지 정리합니다. 직접 넣은 다른 파일은 건드리지 않습니다.
  - 게임 폴더에서 바뀐 모드 파일(스크립트가 저장한 설정, 직접 고친 `.ini` 등)은 모드를 끌 때 지우지 않고 데이터 폴더에
    보관했다가 다시 켜면 되돌립니다(모드를 업데이트하면 새 버전의 파일을 씁니다).
- **게임 폴더 점검**: 적용한 파일이 바뀌거나 없어지면 프로그램을 켤 때 알려 주고, 다시 적용하면 원래대로 돌려 놓습니다.
- **프로필**: 켜 둔 모드, 옵션, 로드 순서를 프로필별로 저장하고 한 번에 바꿉니다 (예: "기본", "사진 촬영용", "바닐라").
- **모드 업데이트 확인 (Nexus Mods)**: 내 Nexus API 키로 설치한 모드에 새 파일이 올라왔는지 확인하고,
  버전 칸에 `1.0 → 1.2`처럼 보여 줍니다.
- **검색과 필터**: 모드 이름 검색(Ctrl+F)과 활성 / 비활성 / 옵션 선택 필요 / 충돌 있음 / 업데이트 있음 필터.
- **다크 / 라이트 테마**와 여러 설정: 창 크기·위치 기억, 게임 실행 전 자동 적용, 실행 후 창 최소화, 삭제 확인 등 (설정 ⚙).
- **기타**: Steam 라이브러리에서 게임 폴더 자동 감지, REFramework 설치 여부 표시, 게임 실행 버튼,
  모드 교체 설치(같은 이름이나 같은 Nexus 모드를 교체할 때 순서·활성 상태 유지), 명령줄(CLI) 지원

## 설치 및 실행

### 방법 1: 실행 파일(.exe)

저장소의 [**Releases**](https://github.com/skagks/asdijofosjifjsioiofasojif/releases/latest) 페이지에서 `MHWildsModManager.exe`를 받아 실행합니다.
설치는 필요 없습니다. 처음 실행할 때 Windows SmartScreen 경고가 뜨면 **추가 정보 → 실행**을 누르세요
(서명되지 않은 실행 파일이라 나오는 경고입니다).

직접 만들려면 Python을 설치한 뒤 `build_exe.bat`를 실행하면 `dist\MHWildsModManager.exe`가 만들어집니다.

### 업데이트

v1.2.0부터는 프로그램이 켜질 때 새 버전을 확인합니다. 새 버전이 있으면 오른쪽 위에 **⬆ 업데이트** 버튼이 생기고,
누르면 변경 내역을 보고 바로 업데이트할 수 있습니다 (내려받은 파일은 SHA-256으로 확인한 뒤 프로그램을 다시 시작하며
교체합니다). ☰ 메뉴 → **업데이트 확인**으로 직접 확인할 수도 있습니다. 그 전 버전을 쓰고 있다면 한 번만 Releases에서
직접 받아 주세요.

> 실행 파일이 `C:\Program Files`처럼 쓰기 권한이 없는 폴더에 있으면 자동 업데이트를 할 수 없습니다.
> 바탕 화면이나 문서 폴더 같은 곳에 두고 쓰세요.

### 방법 2: Python으로 실행

1. [Python 3.10 이상](https://www.python.org/downloads/)을 설치합니다 (설치할 때 *tcl/tk* 포함, 기본값).
2. (선택) 추가 기능 설치: `pip install -r requirements.txt`
   - `tkinterdnd2`: 탐색기에서 파일을 끌어 놓아 설치
   - `Pillow`: JPG 미리보기 이미지 표시, 장비 외형의 게임 그림
   - `py7zr`: 다른 압축 프로그램 없이 `.7z` 압축 풀기
   - `zstandard`: 재질 복구, 장비 외형의 장비 이름 · 그림 (게임 pak 파일의 압축 풀기)
3. `MHWildsModManager.pyw`를 더블클릭하거나 `python -m mhwmm`을 실행합니다.

> `.rar` · `.7z` 파일은 PC에 설치된 **반디집** 또는 **7-Zip**으로 풀어서 설치합니다. 둘 다 없으면 Windows 11에
> 들어 있는 기본 압축 풀기(tar)를 시도합니다. zip 파일은 아무것도 없어도 됩니다.

## 사용법

1. 처음 실행하면 Steam 라이브러리에서 게임 폴더를 찾습니다. 못 찾으면 오른쪽 위 **⌂ 게임 폴더** 버튼 → **다른 폴더 선택...**으로
   `MonsterHunterWilds.exe`가 있는 폴더를 지정하세요.
2. **＋ 모드 추가**를 누르거나 모드 압축 파일을 창에 끌어 놓습니다.
3. 체크박스(또는 더블클릭, 스페이스바)로 켜고 끕니다. **즉시 적용**이 켜져 있으면 바로 게임 폴더에 반영되고,
   꺼져 있으면 **게임에 적용**(Ctrl+S)을 눌러야 반영됩니다.
4. 같은 파일을 바꾸는 모드끼리는 아래쪽 모드가 이깁니다. 오른쪽 **충돌** 탭에서 확인할 수 있습니다.
5. 상황마다 다른 모드 조합을 쓰고 싶으면 툴바의 **프로필** 버튼에서 새 프로필을 만들어 두고 골라 쓰세요.
   새로 설치한 모드는 다른 프로필에서는 꺼진 상태로 들어갑니다.

프로그램 안에서 **F1**(또는 **☰ → 사용법**)을 누르면 주제별로 정리된 사용법과 단축키를 볼 수 있습니다.

### REFramework

루스 파일(`natives`) 모드와 Lua 스크립트는 [REFramework](https://github.com/praydog/REFramework-nightly/releases)가
필요합니다. **이 프로그램에서 바로 설치·업데이트할 수 있습니다.**

- 오른쪽 위 **REFramework 배지**를 누르면 설치된 빌드와 최신 nightly 빌드를 비교해 보여 주고, **설치/업데이트**를 누르면
  `REFramework.zip`을 내려받아(GitHub가 제공하는 SHA-256으로 확인) 게임 폴더에 바로 적용합니다.
- 프로그램을 켤 때 새 빌드가 있는지 확인하고, 있으면 배지가 **REFramework 업데이트**로 바뀝니다 (설정에서 끌 수 있음).
- 직접 넣어 둔 `dinput8.dll`도 몇 번째 빌드인지 알아냅니다. 이 프로그램으로 설치하면 기존 파일은 백업했다가
  REFramework 모드를 끄거나 지우면 되돌립니다.
- REFramework 안내에 따라(VR을 쓰지 않는 경우) `dinput8.dll`만 설치합니다.

루스 파일 모드는 게임 안 REFramework 메뉴의 **LooseFileLoader → Enable Loose File Loader**가 켜져 있어야 합니다.
꺼져 있으면 게임을 실행할 때 **실행 전 점검**이 알려 주고, 묻고 나서 REFramework 설정 파일에서 켜 줍니다(게임이 꺼져 있을 때만).

### 필요한 모드 확인

모드를 설치하면 그 모드가 필요로 하는 다른 모드가 있는지 확인해서, 없거나 꺼져 있으면 바로 알려 줍니다.

- **Nexus 필요 모드**: Nexus에서 받은 파일(또는 Nexus 링크를 설정한 모드)은 모드 페이지의 Requirements 목록을 읽어 옵니다
  (API 키 없이도 됩니다). 설치된 모드와 Nexus 번호나 이름으로 맞춰 보고, REFramework는 설치 여부로 확인합니다.
- **Lua 라이브러리**: REFramework 스크립트가 `require("…")`로 불러오는 파일을 다른 모드나 게임 폴더가 갖고 있는지 확인합니다.
- **셰이더**: 재질 점검에서 재질이 게임에 없는 셰이더(`.mmtr`)를 쓰는 것으로 나오면(셰이더 팩 모드가 넣는 셰이더, 예:
  Endfield Style Shader Pack을 쓰는 의상) 그 셰이더 파일이 든 다른 모드(루스 파일이나 PAK, 옵션까지)나 게임 폴더를 찾습니다.
  그 모드가 꺼져 있거나 셰이더가 든 옵션을 켜지 않았으면 "꺼져 있음", 어디에도 없으면 "없음"으로 알려 줍니다(모드의 옵션 중
  켠 옵션의 재질만 봄). 설치한 뒤 첫 재질 점검에서 없거나 꺼져 있으면 바로 알려 줍니다.
- 결과는 정보 탭의 **필요한 모드**(✓ 있음 · ✕ 없음 · ! 꺼져 있음)에 나오고, Nexus 필요 모드와 Lua 라이브러리는 이름을 누르면
  Nexus 페이지가 열립니다.
  목록에서는 빨간 줄과 ⚠로 표시되고 필터 **필요한 모드 없음**으로 모아 볼 수 있습니다.
- 다른 사이트에 있는 필요 모드는 설치 여부를 알 수 없어 "직접 확인"으로 표시합니다.

### 모드 업데이트 확인 (Nexus Mods)

설치한 모드에 새 버전이 나왔는지 [Nexus Mods](https://www.nexusmods.com/monsterhunterwilds)에서 확인합니다.

1. Nexus에 로그인한 뒤 [API 키 화면](https://next.nexusmods.com/settings/api-keys) 맨 아래의 **Personal API Key**를 복사합니다.
2. 모드 매니저의 **설정 ⚙ → Nexus Mods**에 키를 붙여 넣고 **확인**을 눌러 계정 이름이 나오는지 본 뒤 저장합니다.
3. 프로그램을 켤 때마다 자동으로 확인하고, 결과를 오른쪽 위 **모드 업데이트** 배지에 보여 줍니다 (설정에서 끌 수 있음).
   바로 확인하려면 **☰ 메뉴 → 모드 업데이트 확인 (Nexus)**를 누르세요. 배지를 누르면 업데이트가 있는 모드만 보입니다.

- Nexus에서 받은 파일을 **이름 그대로** 설치하면(`이름-1234-1-0-1740000000.zip`) 어느 모드의 어느 파일인지 알아서 연결합니다.
  이미 설치해 둔 모드도 원본 파일 이름으로 연결됩니다.
- 파일 이름을 바꿨거나 다른 곳에서 받은 모드는 목록에서 **오른쪽 클릭 → Nexus 링크 설정**에 모드 페이지 주소를 넣으세요.
  이 경우에는 모드에 적힌 버전과 Nexus의 최신 메인 파일 버전을 비교합니다.
- 새 버전이 있으면 버전 칸에 `1.0 → 1.2`가 표시되고, 정보 탭의 **Nexus 파일 페이지 열기**(또는 오른쪽 클릭 → 새 버전 받기)로
  파일 페이지를 엽니다. 받은 파일을 창에 끌어 놓고 **기존 모드를 새 파일로 교체**를 고르면 순서와 활성 상태가 유지됩니다.
  모드 이름을 바꿔 두었어도 같은 Nexus 모드의 같은 파일이면 교체할지 묻습니다. 한 모드 페이지에 있는 다른 파일(파일 이름이
  다른 파일, 예: 캐릭터마다 따로 올린 모드)은 묻지 않고 별도의 모드로 설치합니다.
- 다운로드 자체는 Nexus 정책상(프리미엄 회원이 아니면 API로 직접 받을 수 없음) 브라우저에서 합니다.
- API 키는 데이터 폴더의 `state.json`에만 저장되며 Nexus 외에는 보내지 않습니다. 확인할 때 최근 한 달 사이 새 파일이 없는
  모드는 건너뛰어서 Nexus 요청 한도를 거의 쓰지 않습니다.

### PAK 모드는 어디에 들어가나요?

지금의 몬스터 헌터 와일즈는 게임 폴더의 `re_chunk_000.pak.sub_000.pak.patch_NNN.pak` 중 **정품 패치 번호까지만** 읽습니다.
그래서 모드 PAK을 그 뒤 번호로 이름만 바꿔 넣으면 게임이 읽지 않습니다 (텍스처 PAK이면 REFramework가 `[Missing file] ….tex`를 띄움).

이 프로그램은 PAK 모드를 게임 폴더의 **`pak_mods` 폴더**에 넣습니다. REFramework는 이 폴더의 `.pak` 파일을 비어 있는 패치
자리에 차례로 끼워 넣어 불러옵니다.

- 파일 이름은 `001_모드이름.pak`, `002_…`처럼 로드 순서대로 번호를 붙입니다. 번호가 클수록(목록 아래쪽일수록) 우선합니다.
- 순서를 바꾸거나 모드를 끄면 파일을 다시 복사하지 않고 이름만 바꿉니다.
- `pak_mods`에 직접 넣어 둔 다른 파일은 건드리지 않습니다.
- REFramework가 필요하고, REFramework 메뉴의 pak_mods 불러오기(LoadPakDirectory)가 켜져 있어야 합니다 (기본값은 켜짐,
  꺼져 있으면 **실행 전 점검**이 알려 줌).
- v1.6.x 이하에서 패치 번호 방식으로 넣은 PAK은 프로그램을 켤 때 찾아서 `pak_mods`로 옮깁니다 (즉시 적용이 꺼져 있으면 묻습니다).

### 게임 업데이트 후

프로그램을 켤 때 적용한 파일이 바뀌거나 없어졌는지 확인해서 알려 줍니다(또는 오른쪽 위 **☰ 메뉴 → 적용 상태 점검**).
다시 적용하면 원래대로 돌려 놓습니다. 예전 방식으로 넣은 PAK 자리에 게임 업데이트가 공식 패치를 받아 놓았다면, 그 파일은 게임
파일로 두고 지우지 않습니다.

### 재질 복구 (게임 업데이트 뒤 텍스처가 깨질 때)

게임 업데이트로 재질 파일(`.mdf2`)의 구조(텍스처 칸, 셰이더 값)가 바뀌면, 그 전에 만든 의상·무기 모드는 텍스처가 깨지거나
검게·하얗게 보입니다. 지금까지는 MHW Mod Fixer로 모드를 따로 고쳐 다시 설치해야 했는데, 이 프로그램은 설치된 모드를 그 자리에서 고칩니다.

- 프로그램을 켤 때와 모드를 설치한 뒤, 모드의 `.mdf2` 파일과 PAK 안의 재질을 게임 pak에 들어 있는 현재 재질과 비교합니다.
  맞지 않는 모드는 ⚠ 문제로 표시하고 복구할지 한 번 묻습니다. 오른쪽 클릭 → **재질 점검 / 재질 복구**,
  ☰ 메뉴 → **모든 모드 재질 점검**으로 직접 할 수도 있습니다.
- 모드가 베낀 재질(게임의 같은 파일에서 이름이 같은 재질, 또는 같은 셰이더를 쓰는 재질 중 이름이 같은 것이 하나뿐이면 그 재질)이
  있으면 그 재질의 현재 버전과 비교해, 업데이트로 생긴 칸(텍스처 칸·셰이더 값·gpbf 버퍼)이 모드 재질에 없으면 맞지 않는 재질로
  봅니다.
- 그런 재질이 없어 같은 셰이더를 쓰는 다른 재질과 맞춘 경우에는, 현재 게임에서 같은 셰이더를 쓰는 재질 중 모드 재질에 없는 칸이
  하나도 없는 재질이 있으면 그대로 둡니다. 같은 셰이더라도 재질마다 칸이 조금씩 다르기 때문입니다. 그런 재질이 하나도 없을 때만
  맞지 않는 재질로 보고, 복구하면 로그에 가장 가까운 재질과 모드 재질에 없는 칸을 남깁니다.
- 모드가 숨기는 부위에 쓰는 `null`이라는 이름의 재질은 칸이 모자라도 맞지 않는 재질로 보지 않습니다.
- 게임 pak은 게임이 읽는 것만 봅니다. 패치 번호가 비면 그 뒤 PAK은 읽지 않고, 예전 버전의 이 프로그램이 패치 번호로 넣은
  모드 PAK도 뺍니다. 다른 프로그램이 정품 패치 바로 다음 번호로 넣은 모드 PAK은 게임 파일과 구별하지 못합니다.
- 복구는 현재 게임의 재질을 바탕으로 모드의 텍스처 경로, 셰이더 값, 투명도·양면 설정, gpbf 버퍼를 옮겨 담습니다.
  새로 생긴 마스크·디테일 텍스처 칸은 다른 모델의 텍스처가 묻어나지 않도록 게임의 빈 텍스처로 채우고, 이미 맞는 재질은 건드리지 않습니다.
  만든 파일은 다시 읽어서 의도한 내용과 같은지 확인한 뒤에 씁니다.
- 파일 이름의 버전 번호만 바뀐 경우(`.mdf2.40` → `.mdf2.45`)에는 게임이 읽는 번호로 맞춰 줍니다.
- PAK 모드는 재질 항목만 바꾸고 나머지(텍스처, 메시)는 그대로 복사해 같은 순서·압축 방식으로 다시 만듭니다.
- `.user`·`.pfb`·`.scn` 파일(루스 파일과 모드 PAK 안의 항목)은 각 인스턴스의 타입 CRC를 게임 원본과 비교해 오래된 파일을 찾고,
  다음 순서로 고칩니다. 로그에는 `'모드명' <경로>: user 복구 (CRC 갱신)`처럼 남습니다.
  1. **CRC 갱신**: 필드 구성이 그대로면 인스턴스 표의 CRC만 바꿉니다. 나머지 바이트는 그대로입니다.
  2. **재구성**: 필드가 바뀌었으면, 모드가 만들어진 버전의 필드 구성(REasy 타입 덤프의 기록에서 옛 CRC로 찾음)으로 읽어
     현재 구성으로 다시 씁니다. 남아 있는 필드는 모드 값을, 새 필드는 게임 원본 값을 씁니다.
  3. **원본 교체**: 새 필드가 게임 원본의 다른 구성요소를 가리키는 등 다시 쓸 수 없으면, 게임 원본 파일에 모드 값을 필드 이름으로
     옮겨 씁니다(옮기지 못한 값은 로그에 남김). 모드와 원본의 인스턴스는 개수 순서가 아니라 루트에서 이어지는 연결 경로로
     짝짓습니다(업데이트로 중간에 항목이 끼어든 큰 표에서 엉뚱한 항목에 값이 들어가지 않도록). 모드에만 있는 구성요소가 있거나,
     모드가 연결(다른 구성요소를 가리키는 필드)을 원본과 다르게 바꿨거나, 참조하는 파일이 원본과 많이 다르면 하지 않습니다.
     모드 파일을 읽을 수 없을 때는 **원본 그대로 교체**로 표시하고 모드 값은 옮기지 않습니다.
  4. 그 밖에는 건드리지 않고 정보 탭과 로그에 **복구 불가**로 알려 줍니다.

  모든 결과는 현재 필드 구성으로 다시 읽고, 모든 CRC가 현재 값인지, Object 참조는 앞쪽 인스턴스만, UserData 참조는 외부
  설정 파일만 가리키는지, 인스턴스 순서가 원래 파일과 같은지(REasy가 저장할 때 검사하는 규칙)까지 확인한 뒤에 씁니다.
  다시 쓰는 것은 기록에 있는 정확한 옛 구성으로 읽힌 `app.*` 타입뿐이고, 엔진 내장(`via.*`) 타입은 바이트를 그대로 둘 수 있을
  때만 다룹니다. 옛 구성 기록이 없는 CRC에 대해 "필드가 끝에 추가됐을 것"이라고 추측하지 않습니다. 타입 정보는 `mhwmm/matfix/rsz_types.json.xz`에 들어 있고
  (`tools/make_rsz_types.py`로 다시 만듦), 게임 원본 파일이 그 정보로 정확히 읽히지 않으면 그 파일에는 쓰지 않습니다.

  실제 MH Wilds 파일로 확인한 사실: RSZ 버전 16이고 인스턴스 데이터는 파일 끝까지 이어지며, `Resource` 필드는 길이가 붙은
  UTF-16 문자열로 저장됩니다(REasy의 해석). 옛 덤프는 같은 바이트를 다른 이름(`v0`, `v0_Enabled` 등)으로 적어 둔 경우가 많아서,
  현재 구성으로 읽어도 바이트가 똑같이 맞는 인스턴스는 바이트를 그대로 두고, 실제로 필드가 바뀐 인스턴스만 이름으로 맞춰 다시 씁니다.
  바뀌지 않은 인스턴스는 빈 칸(패딩)까지 원래 바이트를 그대로 씁니다.

  MHWmodfixer가 실제 게임에서 확인한 규칙을 따릅니다: CRC가 모두 현재 게임과 같은 파일은 건드리지 않고, 인스턴스를 새로 끼워
  넣지 않으며, 체인 물리 설정(`app.ChainSetting` 등)은 다시 쓰지 않고, 원본 교체 때도 모드가 가리키던 다른 장비의 `.user`
  설정 파일은 그대로 둡니다. CRC는 현재 게임과 같은데 현재 구성으로 읽히지 않는 파일(게임이 잘못 읽어 멈출 수 있음)은
  고치지 않고 알려 줍니다. 고칠 수 없는 파일은 단계별로 왜 안 됐는지 정보 탭과 로그에 남기고, 오른쪽 클릭 →
  **재질 진단 파일 저장**으로 모드 파일·게임 원본 파일·점검 결과를 zip으로 저장할 수 있습니다.

  게임이 업데이트되어 들어 있는 타입 정보가 게임과 맞지 않으면, 이 저장소의 최신 `rsz_types.json.xz`(REasy가 새 덤프를 내면
  GitHub Actions가 매일 확인해 다시 만듦)를 받아 데이터 폴더의 `cache\`에 두고, 고치지 못했던 파일을 다시 점검합니다.
- 고친 파일은 데이터 폴더의 `mods\<id>\matfix\`에 따로 두고, 모드의 원래 파일은 그대로 둡니다. 오른쪽 클릭 →
  **원래 재질로 되돌리기**로 언제든 되돌릴 수 있고, 게임이 다시 업데이트되면 원래 파일에서 다시 복구합니다.
- 처음 점검할 때는 게임 pak 파일 목록을 읽느라 시간이 걸립니다. 목록은 데이터 폴더의 `cache\`에 저장해 두고 게임이 업데이트될 때만 다시 만듭니다.
- 같은 셰이더를 쓰는 게임 재질이 없는 재질은 고칠 수 없어 그대로 두고 로그에 남깁니다. 셰이더 파일 자체가 게임에 없으면(셰이더 팩
  모드가 넣는 셰이더) 그 셰이더가 든 모드를 [필요한 모드](#필요한-모드-확인)로 보여 줍니다.

재질 복구는 [MHWmodfixer](https://github.com/PoeticJustice79/MHWmodfixer)(Littlefish, MIT 라이선스)의 pak·mdf2 읽기/쓰기와
재질·RSZ 복구 규칙을, `.user`·`.pfb` 타입 정보는 [REasy](https://github.com/seifhassine/REasy)(Battlezone, MIT 라이선스)의
MH Wilds RSZ 덤프와 그 기록을 바탕으로 만들었습니다.

### 장비 외형 (모드가 바꾸는 장비 보기)

툴바의 **장비 외형**을 누르면 설치된 모드가 게임 속 어떤 장비의 모습을 바꾸는지 보여 주는 창이 열립니다.
모드를 오른쪽 클릭해 **장비 외형 보기**를 고르면 그 모드가 바꾸는 장비만 보입니다.

- 왼쪽에서 방어구(남성 · 여성), 무기 종류, 사냥벌레, 오토모, 세크레트, NPC, 몬스터 등 분류를 고르고, 검색창에서
  장비 이름이나 모드 이름으로 찾습니다. **켠 모드만**을 켜면 꺼 둔 모드는 빠집니다.
- 장비마다 게임의 미리보기 그림, 이름(같은 모델을 쓰는 본 · 본α처럼 모두), 레어도, 바뀌는 부위가 나오고,
  오른쪽에는 부위별 그림과 그 장비를 바꾸는 모드, 겹치는 부위가 나옵니다. 하위 · α · β가 같은 모습을 쓰면 레어도는
  `레어 1~5`처럼 범위로 나오고, 오른쪽에 장비 이름마다 레어도가 따로 나옵니다.
- 켜 둔 모드 두 개 이상이 같은 부위를 바꾸면 **겹침**으로 표시합니다. 목록 아래쪽(우선순위가 높은) 모드의 모습이 보입니다.
- 모드 파일의 게임 경로(`Art/Model/Character/ch03/004/001/...` 같은 모델 폴더)로 장비를 알아냅니다. PAK 모드는 PAK 안의
  파일 이름 해시를 게임의 장비 파일 목록(`mhwmm/equip/equip_paths.txt.xz`)과 맞춰 봅니다. 다른 장비의 모델을 빌려 쓰는
  프리팹(.pfb)은 "프리팹이 ○○ 모델을 씁니다"로 알려 줍니다.
- 게임에는 남성 · 여성 방어구가 한쪽 폴더의 텍스처를 함께 쓰는 장비가 있습니다. 모드가 그런 게임 텍스처를 바꾸면 다른 성별의
  장비도 함께 바뀐 것으로 나오고, 오른쪽 "참고"에 어느 장비의 텍스처 때문인지 나옵니다. 모드가 자기 이름으로 새로 넣은
  텍스처는 그 모드의 재질만 쓰므로 다른 성별에는 영향이 없습니다.
- 장비 이름 · 레어도 · 미리보기 그림은 설치된 게임의 데이터 표, 텍스트(.msg), GUI 텍스처(.tex)에서 직접 읽어 데이터 폴더의
  `cache\`에 저장해 둡니다. 게임 파일을 이 프로그램에 넣어 배포하지 않으며, 게임이 업데이트되면 다시 읽습니다.
  게임 폴더가 없거나 게임 파일을 읽을 수 없으면 게임 안의 번호(예: `방어구 004-001`)로 보여 줍니다.
- 게임에서 이름과 그림을 읽으려면 zstandard가, 그림을 보려면 Pillow도 필요합니다 (exe에는 모두 들어 있습니다).
- 장비 이름이나 그림이 나오지 않으면 창 오른쪽 아래 **⋯ → 진단 파일 저장**으로 만든 zip을 보내 주세요.
  zip에는 게임의 장비 몇 개로 적용 후 미리보기를 점검한 결과도 글로 들어 있습니다 (게임 그림은 넣지 않습니다).

#### 적용 후 미리보기 (간단한 3D)

- 오른쪽 **바꾸는 모드**의 모드마다 **적용 후** 그림이 나옵니다. 그 모드가 바꾸는 부위를 모드 파일을 적용한 모습으로
  그린 것입니다. 방어구는 머리 · 몸통 · 팔 · 허리 · 다리를 하나씩, 무기는 본체와 보조(방패 · 칼집 등)를 따로,
  오토모 장비는 조각마다 그립니다.
- 그림을 누르면 **원래 모습 | 적용 후**를 같은 구도로 나란히 크게 보여 주고, 모드가 바꾼 텍스처(게임 → 모드)와
  재질 파일(.mdf2)에서 바뀐 색 값(기본 색 · 염색 색 · 발광 색)도 함께 보여 줍니다.
- 모델(.mesh) · 재질 · 텍스처를 모드에서 먼저 찾고, 없는 파일은 게임에서 읽어 이 프로그램이 직접 그리는 간단한 그림입니다.
  **게임과 색 · 광택이 다를 수 있습니다.** 염색 색(컬러 레이어), 빛나는 부분(발광), 반투명(얇은 천 · 유리 같은 막은 구멍
  뚫린 모습으로 그림), 노멀 맵은 그리지 않습니다. 방어구는 몸에 입힌 모습이 아니라 부위 하나씩 그립니다.
- 모드가 부위를 감추면 **숨김**으로 나옵니다. 모드가 가리키는 파일이 모드에도 게임에도 없으면 그 부분을 회색으로 그리고
  부위 이름 옆에 ⚠를 붙입니다 (게임에서 멈추거나 깨져 보일 수 있습니다). 재질 이름이 맞지 않는 부분은 게임처럼 체크무늬로
  그립니다.
- 게임 폴더가 없으면 모드에 들어 있는 파일만으로 그리고(게임 텍스처를 쓰는 부분은 단색), 원래 모습은 그리지 않습니다.
- 그림은 처음 볼 때 그리고(부위 하나에 보통 1초 안팎) 데이터 폴더의 `cache\equip-previews\`에 저장해 둡니다. 모드나 옵션이
  바뀌거나 게임이 업데이트되면 다시 그립니다.

텍스트 파일 형식은 [REMSG_Converter](https://github.com/dtlnor/REMSG_Converter)(dtlnor, MIT)와 REasy(MIT)를,
텍스처의 GDeflate 압축은 [DirectStorage](https://github.com/microsoft/DirectStorage)(Apache-2.0)와 NVIDIA
[libdeflate](https://github.com/NVIDIA/libdeflate)(MIT/Apache-2.0)의 GDeflate 설명을 바탕으로 직접 구현했습니다.
장비 파일 목록은 REasy의 `MHWS_STM.list`(MIT)에서 뽑았습니다 (`tools/make_equip_paths.py`).
적용 후 미리보기의 모델(.mesh) 구조와 재질 규칙은 REasy(Battlezone, MIT)를 바탕으로 했고, 3D 그리기는 이 프로그램을 위해
순수 파이썬으로 새로 썼습니다.

#### 다른 장비로 옮기기 (모드가 바꾸는 장비 바꾸기)

외형 모드는 정해진 장비 하나(예: 방어구 034-001의 몸통)의 모습을 바꿉니다. **다른 장비로 옮기기**는 그 모습을 다른 장비에
입힌 **새 모드**를 만듭니다. 원래 모드는 지우지 않습니다.

- 목록에서 모드를 고르고 위쪽 막대의 **모드 수정** 버튼(**장비 외형** 옆)을 누르면 모드 수정 창이 열립니다. 창 맨 위의
  **모드**에서 다른 모드로 바꿀 수 있습니다(글자를 누르면 그 글자로 시작하는 모드로 갑니다). 모드를 오른쪽 클릭해
  **모드 수정...**을 고르거나, 장비 외형 창에서 장비를 고른 뒤 오른쪽 **바꾸는 모드**의 **다른 장비로 옮기기...**를 눌러도
  같은 창이 열립니다.
- **방어구**는 같은 종류의 다른 방어구로 옮깁니다. 같은 디자인의 남성용 · 여성용 파일을 함께 옮깁니다(남성용은 남성용 장비로,
  여성용은 여성용 장비로).
- **부위마다 다른 장비로**: 창 왼쪽 **부위별로 옮길 장비** 표에 모드가 바꾸는 부위(머리 · 몸통 · 팔 · 허리 · 다리 · 슬링어)가
  나옵니다. 표에서 부위를 고른 뒤 가운데 목록에서 장비를 고르면 그 부위에 입힙니다. 처음에는 모든 부위가 골라져 있어 장비
  하나만 고르면 모든 부위가 그 장비로 갑니다. 예를 들어 머리만 골라 호프 갑옷을, 몸통만 골라 고어 갑옷을 고르면 머리는 호프,
  몸통은 고어를 바꾸는 새 모드 **하나**가 만들어집니다(이름은 "원래 이름 → 머리 <장비 이름> · 몸통 <장비 이름>"). **옮기지 않기**는
  고른 부위를 옮기지 않고(그 부위의 파일은 넣지 않음), **모든 부위 고르기**는 모든 부위를 다시 고릅니다. 키보드로는 Tab으로 표에
  가서 화살표로 고르고, 목록에서 Enter로 입힙니다.
- 한 부위의 파일이 다른 부위의 파일을 가리키면(예: 투구의 머리카락 설정이 몸통 재질을) 그 경로도 그 부위를 옮긴 장비로
  고칩니다. 옮기지 않는 부위의 파일을 옮기는 부위가 쓰면 그 부위와 함께 옮기는데, 서로 다른 장비로 가는 부위들이 함께 쓰면
  만들지 않고 그 부위들을 같은 장비로 옮기거나 그 부위도 옮기라고 알려 줍니다.
- **무기**는 같은 무기 종류의 다른 무기로만 옮깁니다(본체와 보조 모델을 함께, 따로 다른 무기로는 옮기지 않음). 오토모 ·
  세크레트 · 헌터 외모 등은 옮기지 않습니다.
- 파일 이름과 폴더의 장비 번호를 바꾸고, 재질(.mdf2) · 프리팹(.pfb) 안에서 옮긴 파일을 가리키는 경로도 같은 길이로 고칩니다.
  PAK 모드는 PAK 안의 파일을 새 이름으로 다시 넣습니다. 모드가 쓰는 공용 파일(다른 폴더의 텍스처, 모드가 넣은 셰이더 등)은
  그대로 넣고, 다른 장비의 파일 · 고르지 않은 부위 · 스크립트 · 플러그인 · 소리 파일은 넣지 않습니다.
- 만들기 전에 게임 파일로 대상 장비를 확인합니다. 대상 장비에 그 부위가 없거나, 대상 장비가 다른 장비의 모델을 불러와서 옮긴
  모델이 보이지 않을 장비는 만들지 않고 이유를 보여 줍니다(그 부위를 옮기지 않거나 다른 장비를 고르면 나머지 부위는 옮길 수
  있습니다). 이 확인과 아래의 알림은 부위마다 그 부위를 옮길 장비로 합니다. 모드에 모델만 있거나 재질 · 텍스처만 있는 부위는
  원래 장비의 게임 파일로 짝을 맞춰 함께 넣습니다.
- 외형 설정 파일(avp: 머리카락 숨김, 다른 부위와 겹칠 때 숨기는 설정 등)은 옮기지 않습니다. 옮기면 장비 화면이 튕기거나
  장비가 검게 보일 수 있다는 보고가 있어, 대상 장비의 원래 설정을 씁니다. 그래서 머리카락이 투구를 뚫고 나오거나
  다른 부위와 함께 입을 때 일부가 보이지 않을 수 있습니다. 흔들림(chain2) · GPU 옷감이 대상 장비와 다르면 그렇게 알려 줍니다.
- 옵션이 있는 모드는 지금 켠 옵션의 파일만 옮기고, 새 모드에는 옵션이 없습니다.
- **원래 모드 끄기**: 끄면 원래 장비는 게임 모습으로 돌아갑니다. 원래 모드가 다른 장비 · 고르지 않은 부위 · 스크립트나
  그 밖의 게임 파일(아이콘 · 글 · 데이터 등)도 바꾸고 있었다면 그것도 함께 꺼지므로, 그럴 때는 처음에 꺼 두지 않은 채로
  열립니다. 새 모드는 켠 상태로 만들어 원래 모드 바로 아래에 둡니다.
- 새 모드의 재질 점검은 원래 장비의 게임 파일과 비교합니다(옮긴 기록은 모드 폴더의 `mod.json`에 있음). 새 모드를 압축
  파일로 업데이트하면 그 기록은 지웁니다.
- 게임 안에서 직접 확인하지 못한 기능입니다. 모습이 이상하면 새 모드를 지우거나 끄고 원래 모드를 다시 켜면 됩니다.

방어구 · 무기를 다른 장비로 옮기는 규칙(경로 이름, 프리팹이 다른 장비의 모델을 불러오는 경우, 외형 설정 파일)은
[MHWmodfixer](https://github.com/PoeticJustice79/MHWmodfixer)의 적용 방어구 · 무기 변경과 Equip Slot Converter의 설명,
REasy의 파일 목록을 참고했고, 코드는 이 프로그램을 위해 새로 썼습니다.

### 모드 수정 (다른 사람이 만든 모드 고치기)

목록에서 모드를 고르고 위쪽 막대의 **모드 수정**을 누르면 모드 수정 창이 열립니다(오른쪽 클릭 → **모드 수정...**도 같음).
창 맨 위 **모드**에서 다른 모드로 바꿀 수 있고, 왼쪽 **할 일**에서 무엇을 할지 고릅니다. 그 모드에 쓸 수 없는 일은 흐리게
보이고 마우스를 올리면 이유가 나옵니다. 고친 내용은 **저장**을 눌러야 들어가며, 저장하지 않고 닫거나 다른 모드로 바꾸면
버릴지 묻습니다.

- **파일 고르기**: 모드의 파일마다 게임에 넣을지 뺄지 고릅니다(스크립트 · 플러그인 · 텍스처 · PAK 파일 등 무엇이든).
  텍스처 · 모델을 빼면 스트리밍 사본도 함께 뺍니다. 켠 옵션 여럿에 같은 파일이 있으면 **겹치는 파일: 쓸 옵션**에서 어느
  옵션의 것을 쓸지 고릅니다(예: A 옵션의 머리 + B 옵션의 몸통). 보기에서 겹치는 파일 · 다른 모드에 덮어써지는 파일 · 뺀
  파일만 볼 수 있습니다.
- **게임 수치**: 데이터 모드의 `.user` 파일(루스 파일이나 PAK 안)의 값을 바꿉니다. 게임 폴더가 있으면 게임의 원래 파일과
  비교해 **모드가 바꾼 값만** 게임 값 · 모드 값 · 바꿀 값으로 보여 줍니다.
  - 값을 고르고 오른쪽 칸에 새 값을 적은 뒤 **적용**(또는 Enter). **원래 값으로**는 모드의 값으로 되돌립니다.
  - **이 표에서 값이 N인 행 모두**를 켜면 같은 값을 가진 행을 한꺼번에 바꿉니다(예: 판매 가격 99999인 아이템 모두).
  - 여러 값을 고르거나 묶음을 고르면 **한꺼번에 적용**: **값 정하기**(모두 N으로), **게임 값의 몇 배**, **모드가 바꾼 만큼의
    몇 배**(예: 3배 모드를 2배로 → '게임 값의 몇 배'에 2). 게임 파일과 행을 맞추지 못한 값은 건너뛰고 몇 개인지 알려 줍니다.
  - 바꿀 수 없는 값(파일 경로 · 다른 데이터를 가리키는 값 · 종류를 나타내는 값 등)은 흐리게 보이고 이유를 알려 줍니다.
    정수 값 가운데에는 아이템 · 몬스터 번호처럼 종류를 나타내는 것도 있어, 게임에 쓰인 값 밖의 번호로 바꾸면 게임이
    튕길 수 있습니다(오른쪽에 게임에 쓰인 값을 보여 줌).
  - 지금 게임과 형식이 다른(게임 업데이트 전의) 파일은 재질 점검에서 복구한 뒤에 바꿀 수 있습니다.
  - 보상 · 피해량 · 체력 같은 값을 바꾼 채 온라인(멀티플레이)에 나가면 다른 사람에게 영향을 주거나 제재를 받을 수 있습니다.
- **스크립트 설정**: 모드에 들어 있는 Lua · JSON · INI · TOML 설정 파일의 값(숫자 · 켜기/끄기 · 글자)을 바꿉니다. 파일의
  다른 부분(주석 · 순서 · 줄바꿈)은 그대로 두고 그 값 하나만 바꿉니다. 스크립트가 게임 안에서 설정을 저장해 게임 폴더의
  파일이 바뀌었으면 그 파일은 여기서 바꾸지 않고(게임에서 바꾼 설정이 사라지지 않게) 게임 안의 설정 메뉴(REFramework 창)에서
  바꾸라고 알려 줍니다. 스크립트가 게임을 실행할 때 만드는 설정 파일(`reframework\data\`)은 아직 고치지 않습니다.
- **수정 내용**: 이 모드에 한 수정(뺀 파일 · 바꾼 값 · 설정)을 모두 보고 하나씩 또는 **모든 수정 되돌리기**로 되돌립니다.
- **다른 장비로 옮기기**: 위의 [다른 장비로 옮기기](#다른-장비로-옮기기-모드가-바꾸는-장비-바꾸기)와 같습니다. 고친 모드를 옮기면
  고친 내용(뺀 파일 · 바꾼 값)도 새 모드에 그대로 들어갑니다.

알아 둘 점:

- 모드의 원래 파일(`mods\<id>\files\`, `options\`)은 바꾸지 않습니다. 고친 파일은 `mods\<id>\edits\`에, 무엇을 고쳤는지는
  `edits.json`에 따로 두고, 게임 폴더에는 적용할 때 고친 파일을 넣습니다.
- **모드를 업데이트하면** 고친 내용을 새 파일에 다시 적용합니다. 작성자도 같은 값을 바꿨으면 그 값은 작성자 값으로 두고
  **수정 내용**에 "확인할 값"으로 보여 주며, **내 값 유지** / **작성자 값 쓰기**로 고릅니다. 없어진 파일 · 옵션의 수정도 알려 줍니다.
  재질 복구로 파일이 바뀌어도 고친 값을 그 위에 다시 적용합니다.
- 수정은 모든 프로필에 똑같이 쓰입니다. 옵션별 수정은 그 옵션을 켠 프로필에서만 게임에 들어갑니다.
- 원인 모드 찾기 중에는 저장할 수 없습니다. 값 바꾸기는 직접 만든 시험 파일로만 확인했고 게임 안에서는 확인하지 못했습니다.
  게임이 이상하면 **수정 내용**에서 되돌리세요.
- v2.6.0 이하 버전으로 되돌린 뒤 모드를 업데이트하면 수정 내용이 사라집니다.

### 실행 전 점검 (게임을 켜기 전에)

**▶ 게임 실행**을 누르면 게임을 켜기 직전에 모드와 게임 폴더에서 게임이 튕기거나 모드가 작동하지 않는 흔한 원인을 찾아 봅니다.
높음 · 보통 항목이 새로 생겼을 때만 "실행 전 점검: 확인할 것 N개" 창을 띄우고, **그래도 실행**을 누르면 그대로 실행합니다.
실행을 막지는 않으며, 점검이 실패해도 게임은 실행합니다. **☰ 메뉴 → 실행 전 점검**은 낮음 · 참고 항목까지 모두 보여 줍니다.

- 모드: 제대로 작동하지 않는 모드(⚠ 문제)와 재질이 지금 게임과 맞지 않는 모드, 게임 업데이트 뒤 아직 재질 점검을 하지 않은 모드
  (점검 중이면 그렇다고 알림. 새로 설치해 아직 점검하지 않은 모드는 메뉴에서만 보여 줌).
- REFramework: 없거나 꺼져 있는데 루스 파일 · PAK · 스크립트 모드를 켠 경우, 설정 파일(`re2_fw_config.txt`)에서
  `LooseFileLoader_Enabled`(루스 파일 읽기)나 `IntegrityCheckBypass_LoadPakDirectory`(pak_mods 읽기)가 꺼져 있는 경우
  (REFramework가 읽는 방식 그대로: 줄이 없으면 기본값), 게임 업데이트 뒤에도 예전 빌드인 경우(게임 실행 파일의 시각으로 보는 참고용).
- 게임 폴더:
  - `pak_mods`의 PAK이 80개쯤을 넘을 때. 그쯤부터 게임이 시작할 때 튕긴다는 보고가 있으나 정확한 한도는 알려지지 않은 추정치입니다.
  - 매니저가 넣지 않은 PAK(REFramework는 `pak_mods`의 `.pak`을 하위 폴더까지 모두 불러옴)과 확장자가 `.PAK`처럼 대문자라 읽히지 않는 PAK.
  - 매니저가 넣지 않은 DLL: ReShade · OptiScaler 같은 프로그램의 `dxgi.dll` 등과 게임에 들어 있지 않은 DLL · ASI,
    VR을 쓰지 않으면 넣지 말라는 REFramework의 VR 파일(`openvr_api.dll`, `openxr_loader.dll`).
  - 매니저가 넣지 않은 플러그인(`reframework\plugins`) · 스크립트(`reframework\autorun`) · 루스 파일(`natives\`).
    직접 넣은 루스 파일은 재질 점검만 하고(읽기만 함) 고치지 않습니다.
- 지난번 게임의 REFramework 기록: 읽지 못한 파일이 그때 게임 폴더에 있던 모드의 파일이고 그 모드가 지금도 켜져 있으면(그 뒤로
  모드를 업데이트하거나 재질을 복구하지 않았으면) 높음으로 알립니다. 여러 모드에 같은 파일이 있으면 게임이 읽은 쪽(나중 순서의 모드,
  번호가 큰 PAK, 루스 파일 읽기가 켜져 있으면 PAK보다 루스 파일)만 보고, 재질 점검에서 맞는 파일로 나온 것은 낮음으로 둡니다.
  REFramework가 그 게임에서 제대로 시작하지 못했고 그 뒤로 바뀌지 않았을 때도 알립니다.
- 항목마다 **설정 고치기** · **재질 복구** · **재질 점검** · **REFramework 업데이트** · **다시 적용** · **폴더 열기** · **모드 보기**
  같은 버튼이 있습니다. **설정 고치기**는 묻고 나서 REFramework 설정 파일의 그 줄만 바꾸며(줄바꿈 형식 유지), REFramework가
  게임을 끌 때 설정을 다시 쓰므로 게임이 꺼져 있을 때만 바꿉니다. 지난번 게임에서 REFramework가 게임 폴더에 쓰지 못해
  `%APPDATA%\REFramework` 폴더를 썼다면 그 폴더의 설정 파일을 보고 고칩니다.
- **같은 내용이면 다시 묻지 않기**를 켜면 같은 항목은 다시 묻지 않습니다(데이터 폴더의 `precheck.json`). 새 항목이 생기거나
  모드를 업데이트하거나 게임이 업데이트되면 다시 묻습니다.
- 빠른 점검은 폴더 몇 개를 훑어보는 정도라 실행을 늦추지 않습니다. 지난 게임 기록과 직접 넣은 루스 파일의 재질 점검처럼 오래
  걸리는 것은 프로그램을 켤 때 뒤에서 해 두고(`cache\precheck-scan.json`), 메뉴에서 열 때 다시 합니다.
- 원인일 수 있다는 뜻이고 확실하다는 뜻은 아닙니다. 매니저가 넣지 않은 파일은 지우지 않으니 **폴더 열기**로 직접 확인하세요.
  원인 모드 찾기 중에는 묻지 않습니다.

### 게임 튕김 기록 (게임이 튕길 때)

게임이 바탕 화면으로 꺼지면 REFramework가 게임 폴더에 기록(`re2_framework_log.txt`, `reframework_crash.dmp`,
`reframework_faulty_files.txt`)을 남깁니다. 이 기록은 게임을 다시 켤 때 지워지므로(2026-10-11 이후 REFramework는 바로 전
기록 하나를 `re2_framework_log.prev.txt`로 남김), 이 프로그램은 **프로그램을 켤 때**와 **▶ 게임 실행으로 게임을 시작하기 직전에**
기록을 데이터 폴더의 `crashes\`에 복사해 둡니다(최근 10개, 문제 없는 기록부터 정리). 복사만 하고 게임 폴더의 파일은 바꾸거나 지우지 않습니다.

- 지난번 게임이 비정상적으로 종료됐으면 프로그램을 켤 때 목록 위에 알림이 뜹니다(작업을 막지 않음, 기록 하나에 한 번).
  REFramework가 모드 파일을 읽지 못했을 때도 알립니다. **기록 보기** 또는 **☰ 메뉴 → 게임 튕김 기록**에서 볼 수 있습니다.
- **의심되는 원인**에는 기록에서 찾은 것을 그 근거(기록의 해당 줄)와 함께 보여 줍니다. 모드를 단정하지 않고 "의심되는 모드"로만
  말하며, 모드 이름을 누르면 목록에서 그 모드를 고릅니다.
  - REFramework 플러그인(`reframework\plugins\*.dll`)이나 모드가 넣은 DLL에서 오류가 났으면 그 모드를 짚습니다.
  - REFramework가 읽지 못한 파일(게임 업데이트 뒤 검은 화면 · 무한 로딩의 흔한 원인)은 그 파일이 들어 있는 모드를 찾습니다.
    루스 파일은 경로로, PAK 모드는 PAK 안의 파일 이름 해시로 맞춰 보고, 어느 모드에도 없으면 직접 넣은 파일이 있는지
    살펴봅니다. 모드 없이도 기록되는 경우가 있어 켜진 모드에 없는 게임 파일은 약하게 표시합니다. **재질 점검·복구**
    버튼으로 그 모드를 바로 점검할 수 있습니다.
  - 읽다가 멈춘 Lua 스크립트, 오류를 낸 스크립트, 적용되지 않은 PAK, 시작하지 못한 플러그인, 재질이 맞지 않는 모드도 알려 줍니다.
  - 기록은 그 게임을 실행할 때 켜져 있던 모드와 게임 폴더에 넣어 둔 파일로 맞춰 봅니다. 그 뒤에 모드를 끄거나 새로 설치해도
    지난 기록의 의심은 바뀌지 않으며, 지금 꺼져 있는 모드에는 "(지금은 꺼져 있음)"이 붙습니다.
  - 게임 본체(`MonsterHunterWilds.exe`)나 그래픽(D3D12 · 드라이버)에서 오류가 났다고만 나오면 기록만으로는 모드를 알 수
    없습니다(텍스처 · 모델 모드는 이름이 기록에 남지 않음). 이때는 창 아래 **원인 모드 찾기**로 좁혀 봅니다(아래).
- 게임이 그래픽 오류("Fatal D3D error" 등)를 스스로 잡으면 REFramework 기록은 남지 않고, 게임이 게임 폴더의
  `CrashReport\`에 오류 보고서(zip)를 만든 뒤 종료 코드 0으로 꺼집니다. 이 보고서의 오류 내용 글(`CrashReport.txt`)만 복사해
  튕긴 기록으로 남기고, 오류 내용과 할 일을 보여 줍니다 (시스템 정보 · 덤프는 가져오지 않음).
  - `DEVICE_HUNG` · `DEVICE_RESET`은 게임이 맡긴 그리기 작업(잘못 만들어진 명령)을 그래픽카드가 끝내지 못해 Windows가
    그래픽카드를 다시 시작했다는 뜻이고, 대개 그래픽카드 고장이 아닙니다. 모드를 쓰면 모드의 모델 · 텍스처 · 재질 · 셰이더
    파일(특히 게임 업데이트 전에 만든 것)이나 그래픽 플러그인(ReShade · 업스케일러 등) 때문인 경우가 많고, 그래픽 드라이버 ·
    오버클럭 · 프레임 생성 · 오버레이 때문일 수도 있습니다. 그래서 그래픽카드 오류로 보지 않고 **재질 점검·복구**와 **원인 모드
    찾기**를 권하며, 모든 모드를 꺼도 튕기면 드라이버와 설정을 확인하라고 알려 줍니다. `DRIVER_INTERNAL_ERROR`(드라이버 안의
    오류)는 드라이버를 먼저 다시 설치해 보라고 하지만, 모드일 수도 있다고 함께 알려 줍니다.
- 게임이 멈춰서 강제로 껐거나 게임이 자체 오류 창("RE ENGINE - Aborted" 등)을 띄웠는데 보고서가 없다면 기록이 남지 않습니다. 오류 창이나 Windows 이벤트 뷰어 · 안정성 모니터의 문구를 **오류 창 문구** 칸에 붙여 넣으면 PAK 이름(`file looks corrupted`),
  D3D 오류 번호, 오류가 난 모듈 등으로 원인을 찾아봅니다.
- **Lua 스크립트 오류도 기록하기**를 켜면 REFramework 설정 파일(`re2_fw_config.txt`)의 `ScriptRunner_LogToDisk` 한 줄만 바꿔,
  다음 실행부터 스크립트 오류가 기록에 남습니다. 게임이 켜져 있으면 REFramework가 설정을 덮어쓰므로 게임을 끈 뒤에만 바꿉니다.
- **게임이 읽는 파일도 기록하기**를 켜면 REFramework 설정의 `LooseFileLoader_LogAccessedFiles`(루스 파일 읽기가 꺼져 있고
  `natives\` 폴더가 비어 있으면 `LooseFileLoader_Enabled`도)를 켜서, 튕긴 기록에 튕기기 직전 10초 동안 게임이 읽은 모드
  파일(루스 파일 · PAK 모드)이 함께 남고 **의심되는 원인**에 나옵니다. 게임이 꺼져 있을 때만 바꾸고, 로딩이 조금 느려질 수
  있습니다. 끄면 이 창에서 켠 설정을 원래대로 되돌립니다(그사이 루스 파일 모드가 생겼으면 루스 파일 읽기는 켠 채로 둠).
  원인 모드 찾기가 게임 실행 중에 끝나 게임을 끄면 되돌릴 기록이면 체크해서 계속 켜 둘 수 있습니다. 진단 파일에는 이 기록의
  마지막 300줄이 들어갑니다.
- **진단 파일 저장**은 모드 목록(순서 · 켜짐 · 옵션 · 재질 상태 · 없는 필수 모드), 적용 상태 점검, 게임 · REFramework 기록,
  `manager.log`의 마지막 2000줄, 게임 폴더에 넣은 파일 목록을 zip 하나로 저장합니다. 경로의 사용자 이름(`C:\Users\<이름>`)은
  가리고, Nexus API 키가 들어 있는 `state.json`은 넣지 않습니다. 크래시 덤프는 메모리 일부가 들어 있고 그 안의 사용자 이름은
  가리지 못해 **크래시 덤프 포함**을 켰을 때만 넣습니다.
- 매니저를 켜지 않은 채 Steam에서 게임을 다시 실행하면 튕긴 게임의 기록이 지워질 수 있습니다. 게임이 튕긴 뒤에는 먼저
  이 프로그램을 켜거나 **▶ 게임 실행**으로 게임을 시작하세요.

기록 형식은 [REFramework](https://github.com/praydog/REFramework)(praydog, MIT)의 소스를 바탕으로 읽습니다.
REFramework 빌드마다 기록이 조금씩 달라 모르는 줄은 건너뜁니다.

### 원인 모드 찾기 (기록만으로 모드를 알 수 없을 때)

게임 본체나 그래픽 쪽 오류처럼 기록에 모드 이름이 남지 않으면, 모드를 켜고 끄며 실행해 보고 게임을 튕기게 하는 모드를
찾습니다. 기록으로 모드마다 의심되는 정도를 먼저 매기고, 실행할 때마다 가장 많이 좁힐 수 있는 조합을 고릅니다. 기록이 한
모드를 가리키면 3~4번, 단서가 없으면 모드 30개에 7~10번쯤 실행합니다(시작 창에 예상 횟수가 나옴).

1. **게임 튕김 기록** 창의 **원인 모드 찾기** 또는 **☰ 메뉴 → 원인 모드 찾기**를 누릅니다. 시작 창에서 가장 의심되는 모드와
   근거를 확인하고, **언제 튕기나요?**를 고른 뒤 **시작**을 누릅니다.
2. 목록 위 안내 줄의 **▶ 게임 실행**으로 게임을 켜고, 안내 줄에 나온 대로(튕기던 상황 · 플레이 시간) 해 봅니다. 안내 줄에는
   의심되는 모드 수, 가장 의심되는 모드와 그 가능성, 앞으로 몇 번쯤 남았는지가 나옵니다.
3. 게임이 끝나면 **또 튕겼나요?**에 **튕겼어요** · **괜찮았어요** · **잘 모르겠어요 (같은 구성으로 다시)**로 답합니다.
   다음 구성을 고른 뒤(잠깐 걸릴 수 있음) 모드를 켜고 바로 적용합니다(**즉시 적용**이 꺼져 있어도).
4. 결과가 나오면 가능성(%)과 근거를 보고 **이 모드를 끄고 원래 프로필로** 또는 **원래 프로필로**를 고릅니다.
   **진단 파일 저장**에는 실행한 구성과 근거도 들어갑니다.

- **무엇으로 매기나**: 게임 튕김 기록(튕긴 곳이 모드의 플러그인이나 모드가 넣은 파일인지, 읽다가 멈춘 스크립트,
  REFramework가 읽지 못한 파일, 호출 기록, Lua 오류, 게임의 오류 보고서), 재질 점검 결과, 게임보다 오래된 REFramework,
  마지막 정상 종료(`crashes\last_good.json`)와 지난 실행 기록(`crashes\launches.json`, 같은 게임 버전의 최근 실행), 최근에
  설치 · 업데이트한 모드, 모드 종류(플러그인은 텍스처보다 자주 튕김). 기록이 따로 없으면 모든 모드를 같은 정도로 의심하고
  시작합니다.
- **%의 뜻**: 지금까지의 기록과 답을 모두 따졌을 때 그 모드가(또는 함께 켰을 때만 튕기는 두 모드, 각각 튕기는 두 모드,
  모드 문제가 아님) 원인일 가능성입니다. 기록으로 매긴 처음 값은 짐작이라 결과를 정하지는 않습니다. 결과는 그 모드를 켠
  실행(또는 튕김 기록)에서 튕기고 그 모드만 뺀 원인 찾기 실행(나머지는 그대로)에서 괜찮았던 것을 서로 다른 두 쌍 이상(가끔
  튕기면 세 쌍) 확인하고 가능성이 95%를 넘을 때만 냅니다. 그래서 잘못 고른 답 하나(튕기기 전에 게임을 끄고 **괜찮았어요**를
  고른 경우 등)로 엉뚱한 모드를 짚지 않습니다. 지난 실행 기록과 마지막 정상 종료는 가능성만 바꾸고 이 확인에는 쓰지
  않습니다(그때 튕기던 상황까지 갔는지 모르므로). 결과는 의심이고, 가능성과 근거를 함께 보여 줍니다.
- **모드 없이 확인**: 모드와 상관없이 가끔 튕기는 경우(게임 · 드라이버 · 설정 등)에는 켜고 끈 결과가 우연히 한 모드를
  가리킬 수 있습니다. 그래서 결과를 내기 전에 모드 문제가 아닐 가능성이 아직 남아 있으면 모든 모드를 끄고 실행해
  봅니다(안내 줄에 "모드 없이도 튕기는지 한 번 확인합니다"가 나옴, 괜찮으면 필요한 만큼 다섯 번까지). **가끔**을 고르면 더
  엄격하게 봅니다. 모든 모드를 꺼도 튕기면 모드 문제가 아닐 가능성이 올라가고(답한 뒤 안내 줄에 얼마나 올랐는지 나옴) 찾기를
  이어 갑니다. 한 번 튕긴 것만으로 결과를 정하지는 않고, 모드 문제가 아닐 가능성이 95%를 넘고 모든 모드를 끈 실행에서 여러 번
  튕겼을 때 **모드 문제가 아닐 가능성이 높습니다**라는 결과가 나옵니다. 모든 모드를 끈 실행이 몇 번 괜찮았는지(튕겼는지)는
  결과의 근거에 나오고, 모드를 짚었는데 모든 모드를 끈 실행에서도 튕긴 적이 있으면 결과에 그 횟수와 확인해 볼 것을 함께
  적습니다. 튕김 기록의 오류 종류(그래픽 오류 등)와 상관없이 똑같이 합니다. 무엇을 켜든 가끔 튕기는 경우를 완전히 가려내지는
  못하므로(모드 문제가 아닌데 70%쯤 튕기면 열 번에 한 번쯤은 모드를 짚을 수 있음), 결과대로 한 뒤에도 튕기면 원인 찾기를
  다시 해 보세요.
- **언제 튕기나요?**: 켜거나 불러오는 중 · 같은 장소 · 행동에서 매번 · 특정 장비를 입거나 볼 때(장비 외형 창에서 살펴본
  적이 있으면 장비를 고를 수 있고, 그 장비를 바꾸는 모드를 더 의심함) · 한동안 하다 보면(몇 분쯤) · 가끔. 고른 것에 따라
  안내 줄의 할 일과, 한 번 괜찮았던 실행을 얼마나 믿을지가 달라집니다.
- **플레이 시간**: **한동안 하다 보면** · **가끔**을 고르면 지난번에 실행 후 몇 분 만에 튕겼는지(시작 창에 적은 분이 있으면
  그것)로 안내 줄에 "20분 넘게 해 보세요"처럼 권하는 시간이 나오고, 그보다 짧게 하고 괜찮았던 실행은 약하게만 반영합니다.
  같은 장소 · 행동, 특정 장비, 켜거나 불러오는 중을 고르면 그 상황까지 가 보면 되고 플레이 시간은 따지지 않습니다. 튕기던
  상황까지 가지 못했다면 **잘 모르겠어요**를 고르세요.
- **계속 찾기 · 한 번 더 확인**: 정해 둔 횟수 안에 하나로 좁히지 못하면 "아직 하나로 좁히지 못했습니다"와 가장 의심되는
  모드를 보여 줍니다. **계속 찾기**로 6번 더 할 수 있고, 가장 의심되는 모드가 50% 이상이면 그 모드를 끄고 돌아갈 수도
  있습니다. 결과가 두 쌍으로 정해졌으면 **한 번 더 확인**으로 세 쌍째를 확인할 수 있습니다(보통 1~2번 더 실행). 결과가 나오기 전에
  **그만두기**를 누르면 지금까지 가장 의심되는 모드를 알려 줍니다.
- **게임이 읽는 파일을 기록해 더 정확하게 찾기**(시작 창, 꺼져 있는 것이 기본이고 고른 것을 기억함): 원인 찾기 동안
  REFramework 설정(`re2_fw_config.txt`의 `LooseFileLoader_LogAccessedFiles`)을 켜서, 실행마다 게임이 어떤 모드의 파일을
  읽었는지 봅니다(REFramework가 게임 폴더에 남기는 `reframework_accessed_files.txt`). 의심되는 모드의 파일을 한 번도 읽지
  않은 실행(그 장비 · 장소까지 가지 않은 실행)으로는 그 모드를 지우지 않고, 튕기기 직전 10초 동안 읽은 모드 파일도 보여
  줍니다. 게임이 꺼져 있을 때만 바꾸고, 원인 찾기를 마치면 원래 값으로 되돌립니다(게임이 켜져 있으면 데이터 폴더의
  `refw_restore.json`에 적어 두었다가 게임이 꺼진 뒤에). 루스 파일 읽기(`LooseFileLoader_Enabled`)가 꺼져 있으면
  `natives\` 폴더에 파일이 없을 때만 함께 켭니다(켜면 그 파일을 게임이 새로 읽게 되므로). 게임 로딩이 조금 느려질 수
  있습니다. **게임 튕김 기록** 창의 **게임이 읽는 파일도 기록하기**로 계속 켜 둘 수도 있습니다.
- 지금 프로필은 건드리지 않습니다. 현재 프로필을 복제한 임시 프로필 "원인 찾기 (임시)"에서 모드를 켜고 끄고, 끝나거나
  **그만두기**를 누르면 원래 프로필로 돌아간 뒤 임시 프로필을 지웁니다. 진행 상황은 데이터 폴더의 `bisect.json`에 저장되어
  매니저를 껐다 켜도 이어서 합니다(이전 버전에서 시작한 원인 찾기는 그때 방식대로 이어 감).
- 다른 모드에 필요한 모드(REFramework, Nexus 모드 페이지의 필요 모드, 스크립트가 불러오는 Lua 라이브러리, 재질이 쓰는 셰이더가
  든 모드)는 그 모드를 켤 때 함께 켜고, 다른 모드에 파일을 덮어쓰이는 모드는 덮어쓰는 모드와 함께만 켭니다(실제 구성에서 읽히지 않던 파일이 게임에
  들어가지 않도록. 덮어쓰는 모드가 그 모드를 필요 모드로 둔 패치라면 패치만 끈 구성도 해 봅니다). 옵션을 고르지 않은 모드,
  파일이 모두 다른 모드에 밀린 모드(PAK이 있는 모드는 PAK이 늘 들어가므로 빼지 않음. 덮어쓰는 모드를 끌 때 함께 꺼서 그
  파일이 게임에 들어가지 않게 함), 매니저가 넣지 않은 파일(직접 넣은
  `natives\` 파일, 플러그인, 스크립트, `pak_mods`의 PAK, 프록시 DLL)은 빼고 찾고 목록으로 알려 줍니다. 직접 넣었던 파일을
  모드가 덮어쓴 경우(예: 직접 넣은 REFramework의 `dinput8.dll`)에는 그 모드를 끄면 원래 파일이 되돌아오므로
  "(모드를 끄면 되돌아옴)"으로 따로 알려 줍니다.
- 매니저에서 실행한 게임은 끝날 때까지 지켜보고(`MonsterHunterWilds.exe` 프로세스의 종료 코드) REFramework 기록과 게임의
  오류 보고서로 튕겼는지 확인해, 튕긴 것을 확인하면 **또 튕겼나요?**에서 **튕겼어요**를 먼저 골라 둡니다(예: "비정상 종료를
  확인했습니다 (0xC0000005)"). 매니저가 확인한 것과 같은 답은 조금 더 믿고, 답은 직접 고르며 직접 본 것이 우선합니다.
  종료 코드는 모두 `manager.log`에 남습니다. 게임이 아직 실행 중이면 끈 뒤에 답합니다.
- 매니저에서 실행한 게임이 오류 없이(종료 코드 0, 오류 보고서 없음) 3분 넘게 실행되다 끝나면 그때 켜져 있던 모드를 마지막
  정상 구성으로 기억하고, 실행마다 어떻게 끝났는지를 `crashes\launches.json`(같은 게임 버전, 최근 90일 100번)에 남깁니다.
  원인 찾기는 이 기록을 약하게(그때 튕기던 상황까지 갔는지 모르므로) 근거로 씁니다. 튕긴 실행은 튕긴 곳(모듈과 위치)까지
  같을 때만 무게를 두고, 그 뒤로 끄거나 지운 모드가 켜져 있던 튕김(튕김 기록 포함)은 쓰지 않습니다. 원인 찾기 중이 아닐 때 매니저가
  지켜본 게임이 튕기면 목록 위에 알림이 뜹니다.
- 그래픽 오류(DEVICE_HUNG · DEVICE_RESET 등)로 튕긴 기록도 다른 튕김과 똑같이 찾습니다('언제 튕기나요?' 답대로, 모드
  없이 확인하는 것도 다른 기록과 같은 규칙). 모델 · 텍스처 · 재질 · 셰이더 · 이펙트 · GPU 옷감 · 털 파일이나 그래픽 플러그인이 있는
  모드를 조금 더 의심하고(PAK 모드는 게임 장비 경로 목록으로 안의 파일을 알아봄, 이 게임 버전과 맞지 않는 재질이 있으면 더),
  Lua 스크립트 · 데이터만 있는 모드는 조금 덜 의심하며, '모드 문제가 아님'을 더 높게 보지 않습니다. 모든 모드를 꺼도
  튕기면 "모드 문제가 아닐 가능성이 높습니다"라고 알려 줍니다(그때는 그래픽 드라이버 · 설정 확인). v2.2.5에서 시작한 원인
  찾기는 그때 정한 대로(모든 모드를 끈 실행 두 번 포함) 이어 갑니다.
- 원인 찾기 중에는 모드 설치 · 삭제 · 켜기/끄기 · 옵션 · 순서 · 프로필 · 게임 폴더를 바꿀 수 없습니다(명령줄도 같음).
  게임이 업데이트되면 원인 찾기를 멈춥니다.
- 한 번 실행할 때마다 튕기던 상황을 다시 만들어야 해서 시간이 걸립니다. 테스트 중에는 가능하면 게임을 저장하지 마세요.

### 모드를 전부 빼고 싶을 때

**☰ 메뉴 → 게임 폴더에서 모든 모드 파일 제거**를 누르면 이 프로그램이 넣은 파일을 모두 지우고 백업해 둔 원본을
복원합니다. 설치된 모드 목록은 그대로 남아서 나중에 **게임에 적용**으로 다시 넣을 수 있습니다.

## 데이터 저장 위치

| 항목 | 위치 |
| --- | --- |
| 기본 (exe) | 실행 파일과 같은 폴더의 `MHWildsModManager_data` (없으면 자동으로 만듦) |
| exe 폴더에 쓸 수 없을 때 | `%LOCALAPPDATA%\MHWildsModManager` (예: `C:\Program Files`에 둔 경우) |
| Python으로 실행 | `%LOCALAPPDATA%\MHWildsModManager` |
| 직접 지정 | `--data-dir <폴더>` 옵션 또는 `MHWMM_DATA_DIR` 환경 변수 |

v1.2.1 이하에서 `%LOCALAPPDATA%\MHWildsModManager`에 쌓인 데이터는 v1.3.0 이상을 처음 실행할 때 exe 옆으로 자동으로
옮겨집니다. 모드 파일이 데이터 폴더에 저장되므로, 용량이 넉넉한 드라이브에 exe를 두면 됩니다.

- `mods\<id>\files\` : 설치된 모드 파일 (게임 폴더 기준 구조)
- `mods\<id>\matfix\` : 재질 복구로 만든 파일 (모드의 원래 파일은 그대로)
- `mods\<id>\edits\`, `edits.json` : 모드 수정으로 고친 파일과 무엇을 고쳤는지 (모드의 원래 파일은 그대로)
- `cache\` : 재질 점검에 쓰는 게임 파일 목록, 장비 외형에 쓰는 장비 이름과 미리보기 그림, 적용 후 미리보기 그림,
  실행 전 점검의 느린 점검 결과 (게임이 업데이트되면 다시 만듦)
- `crashes\` : 게임 튕김 기록 (게임 폴더에서 복사한 REFramework 기록, 최근 10개; 게임이 읽은 파일 기록은
  `reframework_accessed_files.txt.gz`로 압축해 그 기록 폴더에), 마지막 정상 구성(`last_good.json`), 실행마다 어떻게
  끝났는지(`launches.json`, 최근 90일 100번)
- `bisect.json` : 진행 중인 원인 모드 찾기 (끝나면 지움)
- `refw_restore.json` : 원인 모드 찾기가 게임 실행 중에 끝나 아직 되돌리지 못한 REFramework 파일 기록 설정 (게임이 꺼지면
  되돌리고 지움)
- `refw_logging.json` : 게임 튕김 기록 창에서 켠 REFramework 파일 기록 설정의 원래 값 (그 창에서 끌 때 되돌리고 지움)
- `precheck.json` : 실행 전 점검에서 "같은 내용이면 다시 묻지 않기"로 한 항목 (게임 버전마다)
- `state.json` : 모드 목록, 순서, 활성 상태, 설정
- `deployment.json` : 게임 폴더에 넣은 파일 기록
- `backups\` : 모드가 덮어쓴 원본 게임 파일
- `edited\` : 게임 폴더에서 바뀐 모드 파일 (모드를 끄거나 다른 파일이 그 자리에 들어간 동안 보관하고, 그 파일이 다시
  들어가면 되돌림. 모드 수정으로 바꾼 파일을 되돌린 경우는 보관만 함)
- `manager.log` : 로그

## 명령줄(CLI)

```
python -m mhwmm list                         # 모드 목록
python -m mhwmm game [경로]                  # 게임 폴더 설정 (생략 시 자동 감지)
python -m mhwmm install 모드.zip [--option 2 | --all] [--replace] [--disabled]
python -m mhwmm options "모드 이름"             # 옵션 목록 보기
python -m mhwmm options "모드 이름" --set 1 3   # 1번, 3번 옵션만 켜기
python -m mhwmm enable 1 "모드 이름"          # 번호, 이름, id로 지정
python -m mhwmm disable 3
python -m mhwmm move "모드 이름" 5            # 로드 순서 변경 (아래일수록 우선)
python -m mhwmm remove 2
python -m mhwmm refw [--install]             # REFramework 버전 확인 / 설치·업데이트
python -m mhwmm nexus key <API 키>           # Nexus API 키 확인 후 저장
python -m mhwmm nexus check                  # 설치한 모드의 새 버전 확인
python -m mhwmm nexus link "모드 이름" https://www.nexusmods.com/monsterhunterwilds/mods/1234
python -m mhwmm nexus unlink "모드 이름"
python -m mhwmm profile                      # 프로필 목록
python -m mhwmm profile "사진 촬영용" --create [--empty]   # 새 프로필 (--empty: 모두 꺼진 상태)
python -m mhwmm profile "기본"                # 프로필 전환
python -m mhwmm conflicts [--files]           # 같은 파일을 바꾸는 모드들
python -m mhwmm materials check [모드...]     # 재질이 현재 게임과 맞는지 점검 (생략하면 모든 모드)
python -m mhwmm materials repair [모드...]    # 맞지 않는 재질 복구 (원래 파일은 그대로)
python -m mhwmm materials restore "모드 이름"  # 원래 재질 파일로 되돌리기
python -m mhwmm materials report "모드 이름" --out 진단.zip   # 진단 파일 저장
python -m mhwmm equipment [모드...]          # 모드가 바꾸는 장비 (게임의 장비 이름으로)
python -m mhwmm equipment --icons 아이콘.png  # 게임의 무기 아이콘 위치 확인용 그림 저장
python -m mhwmm equip-preview "모드 이름" weapon/09/000021/main 그림.png [--before] [--size 512]
                                             # 적용 후 3D 미리보기 그림 저장 (--before: 원래 모습도 그림-before.png로)
python -m mhwmm equip-preview --self-test [N] # 게임의 장비 N개로 적용 후 미리보기 점검 (결과는 글로 출력)
python -m mhwmm retarget "모드 이름" --to armor/f/087/000 [--from armor/f/034/001] [--parts helm,body]
                                             # 다른 장비로 옮긴 새 모드 만들기 (--dry-run: 무엇을 옮기는지만 보기,
                                             # --keep-original: 원래 모드를 끄지 않음)
python -m mhwmm retarget "모드 이름" --to helm=armor/f/045/002 --to body=armor/f/060/000
                                             # 부위마다 다른 장비로 (부위=장비, 머리=… 처럼 한국어 부위도 됨.
                                             # 부위 없는 --to를 함께 적으면 나머지 부위는 그 장비로)
python -m mhwmm edit "모드 이름" [status]      # 모드 수정: 이 모드에 한 수정 (뺀 파일 · 바꾼 값 · 확인할 값)
python -m mhwmm edit "모드 이름" files [--overlaps] [--excluded]   # 모드의 파일과 상태
python -m mhwmm edit "모드 이름" exclude|include 경로... [--option 이름]   # 파일 빼기 · 다시 넣기 (패턴 가능)
python -m mhwmm edit "모드 이름" use 경로 --option 이름    # 켠 옵션 여럿에 같은 파일이 있을 때 쓸 옵션
python -m mhwmm edit "모드 이름" values [파일] [--find 글자] [--all]   # 값을 바꿀 수 있는 파일, 한 파일의 값
python -m mhwmm edit "모드 이름" set 파일 주소=값... [--same]   # 값 바꾸기 (--same: 같은 값인 행 모두)
python -m mhwmm edit "모드 이름" scale 파일 (--to N | --times K | --change K) [--field 패턴]
                                             # 한꺼번에: 값 정하기 · 게임 값의 몇 배 · 모드가 바꾼 만큼의 몇 배
python -m mhwmm edit "모드 이름" revert [파일 [주소...]] [--all]   # 되돌리기
python -m mhwmm edit "모드 이름" resolve 파일 (주소... | --every) (--keep | --take)   # 업데이트 뒤 확인할 값
                                             # (쓰는 동작은 모두 --dry-run: 저장하지 않고 보기, --no-deploy)
python -m mhwmm crash list                   # 게임 튕김 기록 목록 (REFramework 기록을 먼저 복사)
python -m mhwmm crash show [번호] [--text 오류문구.txt]   # 의심되는 원인과 근거 (번호 1 = 가장 최근)
python -m mhwmm crash report [번호] --out 진단.zip [--dump]   # 진단 파일 저장 (--dump: 크래시 덤프 포함)
python -m mhwmm crash lua [on|off]           # Lua 스크립트 오류 기록 (REFramework 설정, 게임이 꺼져 있을 때만)
python -m mhwmm bisect start [--record 번호] [--when start|same|time|rare] [--minutes N] [--log-files]
                                             # 원인 모드 찾기 시작 (임시 프로필에서, 첫 구성을 적용)
                                             # --when: 언제 튕기나요 · --minutes: 몇 분쯤 하면 튕기는지 (--when time)
                                             # --log-files: 게임이 읽는 파일 기록 (REFramework 설정, 마치면 되돌림)
python -m mhwmm bisect crashed | fine | retry [--minutes N]
                                             # 게임을 실행해 본 결과 (튕겼어요 · 괜찮았어요 · 같은 구성으로 다시), 다음 구성 적용
                                             # --minutes: 이번에 플레이한 분 (게임을 지켜보지 못했을 때)
python -m mhwmm bisect [status]              # 진행 상황: 의심 순위(%)와 다음 구성 · 결과 (진행 중이 아니면 시작했을 때의 계획)
python -m mhwmm bisect more                  # 아직 좁히지 못함이면 6번 더(계속 찾기), 결과가 나왔으면 한 번 더 확인
python -m mhwmm bisect stop [--disable]      # 원래 프로필로 (--disable: 찾은 모드를 끄고, 아직 좁히지 못함이면 50% 이상일 때만)
python -m mhwmm check [--quick] [--fix]      # 실행 전 점검 (낮음 항목까지 모두, 높음·보통이 있으면 종료 코드 1)
                                             # --quick: 직접 넣은 루스 파일의 새 재질 점검 생략 · --fix: REFramework 설정 고치기
python -m mhwmm deploy | purge | verify
```

`enable`/`disable`/`install` 등은 바로 게임 폴더에 적용합니다 (`--no-deploy`로 끌 수 있음).
`equip-preview`의 장비는 `종류/번호/부위`로 씁니다 (예: `armor/f/004/001/helm`, `weapon/09/000021/sub`, `palico/062/body`).
`equipment` 명령이 장비마다 `종류/번호`를 보여 주고, 모드 자리에 `-`를 쓰면 게임 그대로의 모습을 그립니다.

## 주의 사항

- 같은 게임 폴더에 Fluffy Mod Manager 등 다른 모드 관리자를 같이 쓰면 서로의 파일을 알 수 없습니다.
  이 프로그램은 다른 프로그램이 넣은 파일을 건드리지 않지만, 한 가지 관리자만 쓰는 것을 권장합니다.
- 게임이 실행 중일 때는 PAK 파일이 잠겨 있어 적용할 수 없습니다. 게임을 끈 뒤 적용하세요.
- PAK 모드끼리 같은 파일을 바꾸는지는 충돌 표시(파일 기준)에 나오지 않습니다. 같은 장비 부위를 바꾸는 PAK 모드는
  **장비 외형** 창에서 **겹침**으로 확인할 수 있습니다.

## 개발

릴리즈는 자동입니다. `mhwmm/__init__.py`의 `__version__`(과 `pyproject.toml`의 `version`)을 올리고
`CHANGELOG.md` 맨 위에 그 버전의 변경 내역을 적어 기본 브랜치에 푸시하면, GitHub Actions가 테스트 → exe 빌드 →
릴리즈 생성(`v` + 버전 태그, 릴리즈 노트는 CHANGELOG에서)까지 진행합니다. 버전이 그대로면 릴리즈를 건너뜁니다.

```
pip install pytest zstandard pillow
python -m pytest
```

- `mhwmm/analyzer.py` : 압축 내용 구조 분석
- `mhwmm/deploy.py` : 게임 폴더 적용/해제, pak_mods 배치, 백업
- `mhwmm/manager.py` : 모드 목록·설정·설치
- `mhwmm/matfix/` : 재질 복구 (게임 pak 읽기, mdf2 읽기/쓰기, 재질 대응·복구, `rsz.py` .user/.pfb/.scn 복구)
- `tools/make_rsz_types.py` : RSZ 타입 정보(`rsz_types.json.xz`) 다시 만들기 (REasy 저장소 클론 필요),
  `tools/check_rsz_types.py` : 새로 만든 타입 정보 확인 (빠진 CRC, 실제 게임 파일 읽기)
- `mhwmm/equip/` : 장비 외형 (`paths.py` 게임 경로 → 장비, `scan.py` 모드 파일·PAK 살펴보기, `catalog.py` 게임 데이터에서
  장비 이름·그림 찾기, `msg.py` 텍스트, `tex.py`·`gdeflate.py` 텍스처, `icons.py` 게임 아이콘·레어도 색,
  적용 후 미리보기: `mesh.py` 모델 읽기, `render.py` 3D 그리기, `look.py` 모드·게임 파일 고르기, `selftest.py` 점검),
  `mhwmm/equipview.py` : 장비 외형 창, `tools/make_equip_paths.py` : 장비 파일 목록(`equip_paths.txt.xz`) 다시 만들기
- `mhwmm/crashlog.py` : REFramework 기록(로그 · 읽지 못한 파일 목록 · 설정)과 게임 오류 창 문구 읽기,
  `mhwmm/crashes.py` : 게임 튕김 기록 모으기 · 모드와 맞춰 보기 · 진단 파일 (테스트는 직접 만든 가짜 기록으로)
- `mhwmm/bisect.py` : 원인 모드 찾기 (구성 · 결과 글, 임시 프로필, `bisect.json`), `mhwmm/bisect_engine.py` : 원인
  찾기의 확률 계산(원인 후보, 답의 무게, 다음 구성 고르기, 결과를 내는 규칙), `mhwmm/evidence.py` : 기록 · 지난 실행 ·
  재질 상태로 처음 의심 정도 매기기, `mhwmm/accessed.py` : REFramework의 게임이 읽은 파일 기록 읽기와 그 설정 켜기 ·
  되돌리기, `tools/bisect_sim.py` : 원인 찾기 모의 실험 (CI에서는 돌리지 않음),
  `mhwmm/gamewatch.py` : 게임 프로세스가 어떻게 끝났는지 확인 (Windows API, 마지막 정상 구성, 실행 기록)
- `mhwmm/precheck.py` : 실행 전 점검 (빠른 점검, 뒤에서 하는 느린 점검, "같은 내용이면 다시 묻지 않기")
- `mhwmm/gui.py` : tkinter GUI, `mhwmm/theme.py` : 색상·글꼴·스타일, `mhwmm/cli.py` : 명령줄
- `tools/make_assets.py` : 체크박스·스위치·아이콘 이미지 다시 만들기 (Pillow 필요)
